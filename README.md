# وبلاگ علی حسین‌زاده

وبلاگ فارسی و راست‌چین ساخته‌شده با [Hugo](https://gohugo.io/) و منتشرشده از طریق GitHub Pages.

## امکانات

- محتوای فارسی با پشتیبانی RTL و فونت فارسی
- جست‌وجو، برچسب‌ها و دسته‌بندی‌ها
- فهرست تاریخچه، ابرواژه‌ها و پیشنهاد مطالب مرتبط
- RSS و خروجی JSON برای قابلیت‌های سمت کاربر
- تصاویر محلی‌شده از آرشیو ویرگول، به‌همراه حفظ پیوندهای خارجی باقی‌مانده
- نظرها با Giscus و آمار بازدید با GoatCounter، در صورت فعال بودن تنظیمات سرویس‌ها

## ساختار پروژه

- `content/posts/`: مطالب منتشرشده
- `static/`: فایل‌های ثابت و دارایی‌هایی که مستقیماً کپی می‌شوند
- `layouts/` و `assets/`: قالب‌ها، استایل‌ها و اسکریپت‌های سفارشی
- `hugo.toml`: تنظیمات سایت، زبان، آدرس اصلی، taxonomy و خروجی‌ها
- `.github/workflows/hugo.yml`: ساخت و انتشار سایت در GitHub Pages
- `.github/workflows/validate-hugo.yml`: بررسی خودکار ساخت Hugo در درخواست‌های ادغام و شاخهٔ قالب
- `.github/workflows/optimize-large-images.yml`: تبدیل امن تصاویر بزرگ به WebP، فقط با صرفه‌جویی حداقل ۳۰٪
- `.github/workflows/import-virgool.yml`: گردش‌کار واردکردن محتوای ویرگول
- `.github/workflows/vendor-virgool-images.yml`: گردش‌کار محلی‌سازی تصاویر ویرگول
- `.github/workflows/generate-post-thumbnails.yml`: تولید تصاویر بندانگشتی مطالب

## اجرای محلی

برای پیش‌نمایش تغییرات، Hugo را نصب کنید و در ریشهٔ مخزن اجرا کنید:

```bash
hugo server --buildDrafts
```

برای ساخت نسخهٔ نهایی:

```bash
hugo --minify
```

خروجی در پوشهٔ `public/` ساخته می‌شود. در صورت نیاز به تطبیق با نسخهٔ مورد استفاده در GitHub Actions، نسخهٔ Hugo را از فایل گردش‌کار انتشار بررسی کنید.

## افزودن یا ویرایش مطلب

1. یک فایل Markdown در `content/posts/` بسازید یا مطلب موجود را ویرایش کنید.
2. فرادادهٔ ابتدای فایل (front matter) را حفظ کنید؛ به‌ویژه `title`، `date`، `summary`، `categories` و `tags` در صورت وجود.
3. در صورت تغییر مسیر یا نام تصویر، همهٔ ارجاعات همان مطلب را بررسی کنید.
4. تغییرات را در یک شاخهٔ جداگانه بررسی کنید و پس از موفقیت بررسی‌های خودکار ادغام کنید.

## واردکردن محتوا و تصاویر

گردش‌کارهای مربوط به ویرگول در پوشهٔ `.github/workflows/` قرار دارند. پیش از اجرای دستی هر گردش‌کار واردسازی یا محلی‌سازی تصویر، ورودی‌ها و گزینه‌های آن را مرور کنید و تغییرات تولیدشده را بازبینی کنید؛ این فرایندها ممکن است تعداد زیادی فایل محتوا یا تصویر را تغییر دهند. تصاویر خارجیِ باقی‌مانده لزوماً به‌صورت خودکار محلی نشده‌اند.

## نظرها و آمار بازدید

تنظیمات Giscus و GoatCounter در `hugo.toml` قرار دارند. فعال‌بودن عملی آن‌ها به تنظیمات متناظر در سرویس‌های خارجی و دسترس‌پذیری آن‌ها وابسته است؛ وجود تنظیمات در مخزن به‌تنهایی تضمین نمی‌کند که هر دو سرویس در سایت زنده کار می‌کنند.

## انتشار و عیب‌یابی

پس از push یا ادغام تغییرات در شاخهٔ اصلی، وضعیت گردش‌کار GitHub Pages را در زبانهٔ **Actions** بررسی کنید. پیش از ادغام تغییرات مربوط به قالب، جست‌وجو یا تصاویر، ساخت Hugo و صفحات اصلی، یک مطلب نمونه، جست‌وجو و نمایش موبایل را بررسی کنید.
